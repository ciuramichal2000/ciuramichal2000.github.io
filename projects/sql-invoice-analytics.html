sql-invoice-analytics

Accounts-payable analytics written as plain SQL: aging report, running totals, vendor shares, duplicate detection, payment behaviour and invoice status.

The problem

The questions a finance team asks of its invoices are the same every month: what do we still owe and for how long, how much did we spend with each vendor, did we receive the same invoice twice, who do we pay late. Each of them is one SQL query. This project keeps every question in its own readable .sql file, runs them from a small Python program, and tests each one against a dataset whose answers were worked out by hand.

An aging report

What is still owed on a given date, grouped by how overdue it is. It can be run for any past date, because payments made after that date are ignored.

Overpaid and fully paid invoices owe nothing, so they never appear. FV/2026/002 owes 300.00 and FV/2026/003 500.00, both 59 days past due: the two invoices in the 31-60 bucket add up to 800.00.

Window functions: shares and ranks

A self join: possible duplicate invoices

Behaviour of each vendor's invoices

Only invoices paid in full count, and the last payment date decides. A negative average means invoices were paid before they were due.

Decisions worth mentioning

  • Amounts are integer cents. Sums and comparisons are exact; the program turns cents into money only when printing.
  • The schema defends the data: CHECK constraints, foreign keys switched on (SQLite ignores them unless asked), unique invoice numbers, and tests that prove bad data is rejected.
  • The expected answers in the tests are worked out by hand on a small dataset, not copied from the program's output, so a wrong query cannot pass by agreeing with itself.

Tests

11 passed in 0.02s Covered: the aging buckets and the as-of date, running totals, shares and ranks, duplicate pairs, payment behaviour, statuses, the schema rejecting bad data, money conversion and the command line. A GitHub Actions workflow is included; it runs once the repository is on GitHub (it has not been run yet).

Stack: SQL (SQLite with window functions), Python 3 (standard library only), pytest, Git.
