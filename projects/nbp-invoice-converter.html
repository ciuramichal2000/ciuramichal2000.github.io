nbp-invoice-converter

Converts foreign-currency invoices to PLN with the official NBP rate of the last working day before the invoice date.

The problem

A Polish company invoices in euros or dollars, and for VAT the amounts have to be shown in PLN at the official National Bank of Poland (NBP) rate. The rate to use is that of the last working day before the invoice date. That is not always the previous day: weekends and public holidays have no published rate, and the NBP API answers 404 "no data" for them. An invoice dated Monday therefore uses Friday's rate.

How it works

The function steps back one day at a time (up to ten) until the API returns a rate, and raises an error rather than returning a guess if it finds none.

Telling "no rate" from "broken"

A 404 means there is no rate that day. Anything else (a network failure, a server error) is raised, so a temporary outage can never be mistaken for a holiday and silently produce a wrong conversion. One of the tests starts a small local HTTP server to prove exactly this: 404 becomes "no rate", a 500 is raised.

Decisions worth mentioning

  • Money on Decimal, rounded half up to the grosz. No floating-point noise in the books.
  • A cache per currency and day, including the answer "no rate that day", so a batch of invoices asks the API once per day and currency.
  • A bad row does not stop the batch. It gets its own error value and the exit code becomes 1.
  • Honest about tax rules. VAT conversion has variants (rate before the tax point or before the invoice date). The tool implements one and says so; it is a helper, not tax advice.

Tests

9 passed in 0.55s None of them needs the network: the HTTP call is injectable. Covered: the weekend step-back, the day of issue never being used, PLN needing no request, the cache, half-up rounding on decimals, bad rows and the exit code, and the 404 versus 500 behaviour above.

Stack: Python 3 (standard library only), the public NBP Web API, pytest, Git.
